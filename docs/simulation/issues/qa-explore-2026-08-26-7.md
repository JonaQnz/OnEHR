Category: bug

## What I was trying to do

Fill the two-page "Anamnese" composition (Diagnosen + Medikation blocks) for
a patient: `start_composition_session`, `launch_form` + `patch_form_session`
for each block's child form (both fully filled, all required fields
present), then `attach_composition_block` for each.

## What happened

Right after `attach_composition_block` for a child session that already had
complete, valid values, the composition session reported that child as:

```json
{ "status": "in_progress", "valid": false, "issues": [] }
```

`valid: false` with an empty `issues` array - i.e. it looks invalid but no
reason is given, because it hasn't actually been validated yet at that
point (`attach_composition_block` doesn't run validation). Calling
`validate_composition_session` afterwards correctly flips it to
`{ "status": "ready", "valid": true, "issues": [] }`.

## What I expected

Before validation has run, a block's state should be represented as
"not yet validated" (e.g. `valid: null`/`undefined`, or simply omitted)
rather than `valid: false`. `false` reads as "checked and found invalid,"
which is misleading - if this same shape drives a composition UI's
per-page status icons, every newly-attached block would show a red/invalid
indicator before the user has done anything wrong, which is confusing
(especially compounded by `qa-explore-2026-08-26-6.md`-style eagerness to
mark things before they're actually assessed).
